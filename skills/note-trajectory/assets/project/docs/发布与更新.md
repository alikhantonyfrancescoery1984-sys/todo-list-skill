# 发布与用户可选更新 · 0.7.2

本项目没有后台静默安装。用户运行插件命令“待办清单: 检查更新”，确认后才下载并安装。仅修改本地源码不会更新别人的电脑，必须发布正式 GitHub Release。

## 作者：在此项目更新后发布

1. 修改代码；将 manifest.json、package.json、package-lock.json 的版本更新为同一个 x.y.z（每次递增，不能复用已发布标签）。最低 Obsidian 版本由 manifest.json 的 minAppVersion 指定。
2. 在项目根目录运行：

```sh
npm run release:prepare
```

该命令执行类型、行为测试和双构建，生成干净的 Skill/源码树，并在 artifacts/release-版本/ 准备 main.js、manifest.json、styles.css、update.json。此步骤不推送、不发布。

3. 审阅生成的文件，确认目标仓库；首次发布需已安装并登录 GitHub CLI（gh auth login），Git 可访问自己的公开仓库。然后显式执行：

```sh
npm run release:publish
```

命令重新准备并校验，检查目标仓库和远端主线，提交 publication/todo-list-skill 中的干净分发文件，推送 main 和同版本标签，创建正式 Release，上传四个独立附件并标记 Latest。不是只上传 ZIP。不会强推或覆盖旧版本；重复版本、远端主线不同或其它错误会停止。若推送已成功但 Release 创建失败，应检查远端状态后用下列命令补建，不能复用该版本重跑提交：

```sh
# 将 0.7.3 替换成实际已经推送且尚无 Release 的版本
 gh release create 0.7.3 artifacts/release-0.7.3/main.js artifacts/release-0.7.3/manifest.json artifacts/release-0.7.3/styles.css artifacts/release-0.7.3/update.json --repo alikhantonyfrancescoery1984-sys/todo-list-skill --verify-tag --title 0.7.3 --generate-notes --latest
```

发布命令需要在原开发项目执行。随 Skill 的便携源码副本缺少作者仓库与打包工具，不应直接代表作者发布。源码修改与 GitHub 发布是两个独立动作，日常修改不会自动执行公开发布。

## 用户：第一次与后续更新

- 已安装 0.7.2 之前的版本：它们没有新命令，需先手动安装含该功能的版本一次。升级只替换 main.js、manifest.json、styles.css，保留原 data.json；不要复制演示状态。
- 在 Obsidian 命令面板运行“待办清单: 检查更新”。插件只请求固定公开仓库的最新正式 Release，不需要会员或 API key。
- 有新版时展示版本与说明，选择“暂不更新”不会替换任何程序。点击“确认更新”才下载，验证 SHA-256、插件ID、版本和 Obsidian兼容性。
- 校验后备份三个旧程序到当前插件目录的 .update-backup/版本-时间戳/，替换程序并读回核对；写入失败尝试回滚全部旧程序。data.json 不在更新文件列表。
- 安装成功后，关闭再开启“待办清单”插件或重启 Obsidian加载新版。当前运行的旧代码不会在写文件后自动换成新版。
- 网络、GitHub限流、缺少附件等会提示，可稍后重试；校验失败不写文件。程序备份不能替代个人任务数据备份。

## 本次交付的边界

已实现命令和发布脚本，并用合成网络/文件接口测试，不代表已经公开发布本次版本。必须由作者执行 release:publish，用户才能在 GitHub 获取该版或未来版本。单独更新 Codex Skill 不会自动更新 Obsidian 插件。

## 官方依据（通过 Context7 核对）

- [Obsidian 发布要求](https://docs.obsidian.md/Plugins/Releasing/Submit+your+plugin)：标签与 manifest 版本匹配，独立上传 main.js、manifest.json、styles.css。
- [Obsidian API](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)：addCommand、requestUrl、DataAdapter 文件接口。
- [GitHub CLI release create](https://cli.github.com/manual/gh_release_create)：附件、verify-tag、generate-notes 和 latest 参数。
